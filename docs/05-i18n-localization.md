# I18n and Localization

## اللغات

- العربية `ar`: اللغة الاساسية عند الاطلاق.
- الانجليزية `en`: جاهزة تقنيا، ويمكن تفعيل المحتوى عند توفره.

## اتجاه الواجهة

- العربية: `dir="rtl"`.
- الانجليزية: `dir="ltr"`.
- لا تعتمد على CSS مخصص لكل اتجاه كلما امكن. استخدم logical properties مثل `padding-inline`, `margin-inline`, `inset-inline`.

## URL strategy

اقتراح:

```text
/ar
/ar/services
/ar/services/design-permits
/en
/en/services
```

يمكن جعل العربية بدون prefix اذا كان مطلوبا تسويقيا، لكن وجود prefix لكل اللغات يقلل الالتباس ويجعل SEO اوضح.

## Nuxt i18n

المشروع يحتوي `@nuxtjs/i18n`، لذلك يجب ضبط:

- locales: `ar`, `en`.
- defaultLocale: `ar`.
- strategy: `prefix`.
- detectBrowserLanguage بحذر حتى لا يضر SEO.
- alternate links وhreflang.

## النصوص الثابتة

كل النصوص داخل المكونات يجب ان تأتي من ملفات ترجمة:

```text
app/i18n/locales/ar.json
app/i18n/locales/en.json
```

لا تكتب عناوين الازرار والرسائل مباشرة داخل المكونات.

## المحتوى الديناميكي

الخدمات، المشاريع، المقالات، وFAQ يجب ان ترجع من API حسب اللغة.

مثال response:

```json
{
  "id": 1,
  "slug": "design-permits",
  "title": "التصميم واصدار التراخيص",
  "summary": "خدمة متكاملة للتصميم وتجهيز متطلبات الترخيص.",
  "locale": "ar"
}
```

## Slugs

لـ SEO الافضل:

- استخدم slugs انجليزية مستقرة للخدمات اذا لم تكن هناك حاجة قوية للعربية.
- يمكن دعم slug مترجم لاحقا، لكن هذا يزيد تعقيد الربط.

اقتراح MVP:

```text
/ar/services/design-permits
/en/services/design-permits
```

## الارقام والتواريخ

- استخدم تنسيق مناسب للغة.
- في السعودية اعرض ارقام الجوال بصيغة واضحة.
- لا تخلط بين التقويم او المنطقة الزمنية دون قرار واضح.

## المحتوى العربي

النبرة:

- رسمية.
- هندسية.
- مباشرة.
- مطمئنة.
- غير مبالغ فيها.

تجنب العبارات العامة مثل "افضل شركة" دون دليل. ركز على وضوح الخطوات والخبرة والمنهجية.

## QA للغات

قبل الاطلاق:

- راجع عدم انقلاب الايقونات الاتجاهية.
- افحص النماذج بالعربية على الجوال.
- افحص طول النصوص الانجليزية داخل الازرار.
- تأكد من `html lang` و`dir`.
- تأكد من `hreflang`.
